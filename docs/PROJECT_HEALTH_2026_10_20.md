# Проверка проекта — 20 октября 2026

Проверен `sasha-math-bot-2`, исходный опубликованный коммит `b5d39c8`.
Отчёт фиксирует состояние данных на момент аудита. Описанные ниже исправления
включены в обновление сессий; результат его публикации проверяется отдельным этапом.
Новая миграция SQL для этого исправления не требуется.

## Причина жалобы

В учительской сессии JWT обновлялся только таймером раз в 55 минут. При сне ноутбука,
фоновой вкладке или восстановлении старой страницы запрос успевал уйти с истёкшим JWT.
Это воспроизведено на исходном коде и проверено после исправления в браузере с настоящим
Supabase SDK и тестовыми HTTP-ответами.

Supabase за 19 октября зафиксировал:

| Запрос | Отказы |
| --- | ---: |
| `get_review_queue_self` | 4 × 401 |
| `publish_weekly_plan_self` | 3 × 401 |
| `get_teacher_journal_self` | 1 × 401 |
| `admin_list_season_v2_self` | 1 × 401 |
| `sign-upload` | 4 × `token_expired` |
| `teacher-refresh` | 1 × истекшая refresh-сессия |

В базе есть **327 октябрьских заданий у 18 учеников**: 295 ежедневных и 32 еженедельных.
Дата последнего задания — **18 октября**. На неделю **19–25 октября** опубликованных
планов нет. Ошибка публикации не является успешным сохранением: план необходимо
опубликовать из учительской после обновления сайта и входа. Содержимое неотправленного
плана невозможно достоверно восстановить по журналам сервера.

Все 327 октябрьских строк получают корректную дату в функции журнала. Ограничения
только сентябрём в коде нет. Обычные опоздания остаются пропусками; исключение учителя
по-прежнему должно включаться явно.

## Подготовленное исправление

- Проверка срока JWT перед каждым запросом Supabase и перед загрузкой файла.
- Обновление после возврата к вкладке, восстановления сети или фокуса окна.
- Одно общее обновление сессии для параллельных запросов вместо нескольких ротаций.
- Один повтор запроса только после явного отказа `JWT expired`. Сетевые сбои, 403,
  ошибки бизнес-логики и 5xx автоматически не повторяют операции записи.
- Истёкшая 12-часовая сессия учителя возвращает экран входа. Срок сессии на сервере
  не увеличивается. Временный сбой сети не удаляет refresh-токен.
- Выход из аккаунта не может быть отменён запоздалым ответом фонового обновления.
- При повторном входе сохраняются заполненный план и выбранная группа.
  Отсутствие выбранной аудитории больше не превращается в публикацию всем ученикам.
- Аналогичная защита ученической сессии. Режим клиента приведён к уже действующему
  в базе `enforced`: ошибку авторизации больше не скрывает переход к анонимному клиенту.
- Кнопки «Текущий месяц», «Прошлый месяц», «30 дней» в журнале и пояснение для пустого периода.
- Обновлены версии изменённых ресурсов, чтобы браузер загрузил совместимые JS-файлы.
- Исправлен ложный отказ проверки сезонов: слово «период» в подсказке журнала ошибочно
  считалось техническим названием сезона.

В логах обоих ботов есть кратковременные ошибки Telegram: Bad Gateway,
Connection reset, Request timeout и ограничение GetUpdates. После них присутствуют
`Connection established`; например, ученический бот восстановился 19 октября в 04:11:55,
родительский — в 04:13:19 МСК, а после сброса соединения 20 октября — в 00:49:09.
Признаков остановки процессов после этих ошибок в просмотренных логах нет.

У четырёх получателей уведомления отклоняются Telegram: бот заблокирован пользователем
или `chat not found`. Такие получатели должны разблокировать нужного бота и открыть
с ним диалог через `/start`. Изменение журнала эту причину недоставки не устраняет.
Других сообщений прикладного логгера у родительского сервиса за выбранную неделю не найдено.

Настройки, переменные, реплики и деплои Railway во время проверки не изменялись.
